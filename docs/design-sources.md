# 设计来源

本项目的整体架构主要来自 [mattpocock/skills](https://github.com/mattpocock/skills)，并吸收了 [obra/superpowers](https://github.com/obra/superpowers) 中经过实践验证的工程约束。

| 本仓库                  | 来自 mattpocock/skills                                                 | 吸收自 obra/superpowers                                                                                                                                                           |
| ----------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 整体架构                | 仅用户触发与可自动触发的 skill、路由、小而可组合、由人掌控流程         | 不采用会话启动钩子，保持由人决定流程                                                                                                                                              |
| `grilling`              | 设计树、待确认项、分轮追问、事实归 agent 而决策归用户                  | 无                                                                                                                                                                                |
| `to-spec`               | 综合现有讨论、商定测试接缝、内联规格模板                               | 无                                                                                                                                                                                |
| `to-tickets`            | 端到端最小闭环切分、明确前置依赖、预备性重构、扩展-迁移-收缩、核对确认 | 无                                                                                                                                                                                |
| `implement-spec`        | 按当前可执行任务并行推进、工作树、上下文指针                           | 持久化进度、状态契约、代行决策、重试上限、分范围复审和最终修复、同类小改动合并派发、工作树检测与创建（与 `implement` 共用）、用脚本生成评审材料、合批评审逐文件核对、复审判定标准 |
| `tdd`                   | 约定测试接缝、端到端切片、重构移出循环                                 | 确认测试能准确失败、先写代码就重来、变异检查、mock 层级与完整性、测试警示信号清单、常见借口对照表                                                                                 |
| `diagnosing-bugs`       | 优先建立快速反馈、最小化问题、提出可证伪假设、添加调试日志             | 根因回溯、多层校验、条件等待、跨组件边界插桩、连续失败后重新检查架构、定位污染环境的测试、找不到根因时的收尾、常见借口对照表                                                      |
| `code-review`           | 从规范和规格两个维度并行评审、Fowler 代码坏味道基线                    | 严重程度分级、评审者只读、无法核实项明确标记、上线风险维度（迁移、兼容性、安全、性能）                                                                                            |
| `verifying-completion`  | 无                                                                     | 声称完成前必须提供当前状态下的新鲜验证证据                                                                                                                                        |
| `receiving-code-review` | 无                                                                     | 先核实意见再实施，不做表面附和                                                                                                                                                    |
| `finishing-a-branch`    | 无                                                                     | 验证后由用户选择合并、创建 PR 或保留分支，并安全清理工作树                                                                                                                        |
| `writing-for-agents`    | 上下文指针、信息层级、先导词、文档精简                                 | 使用压力场景和子代理验证 skill，description 只描述触发条件，按失败类型选择写法，措辞对照测试与事后追问                                                                            |
| `writing-chinese`       | 概念着陆（Grounding）、节拍编排（Beats）、想法碎片开采与承重词提炼     | 以 GB/T 15834 和 GB/T 15835 为书写规范基础，增加面向 agent 的读者、结构、指代、语义保真和分层审校流程                                                                             |

中文版本保留这些行为约束和设计意图，但不要求逐句对应英文原文。术语选择和表达方式遵循 [中文写作规范](./chinese-writing.md)。
