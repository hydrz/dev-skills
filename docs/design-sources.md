# 设计来源

本项目的整体架构主要来自 [mattpocock/skills](https://github.com/mattpocock/skills)，并吸收了 [obra/superpowers](https://github.com/obra/superpowers) 中经过实践验证的工程约束。

| 本仓库                  | 来自 mattpocock/skills                                         | 吸收自 obra/superpowers                                              |
| ----------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------- |
| 整体架构                | 仅用户触发与可自动触发的 skill、路由、小而可组合、由人掌控流程 | 不采用会话启动钩子，保持由人决定流程                                 |
| `grilling`              | 决策问题之间的依赖关系、分轮追问、事实归 agent 而决策归用户    | 按工作规模调整流程，但始终保留实施前确认                             |
| `to-spec`               | 综合现有讨论、测试接缝、规格模板                               | 检查占位符、一致性、歧义、范围和全局约束                             |
| `to-tickets`            | 端到端最小闭环任务、前置依赖、扩展、迁移、收缩                 | 明确任务间的依赖与提供关系，检查覆盖与类型一致性                     |
| `implement-spec`        | 按当前可执行任务并行推进、工作树、上下文指针                   | 持久化进度、状态契约、代行决策、重试上限、分范围复审和最终修复       |
| `tdd`                   | 约定测试接缝、端到端切片、重构移出循环                         | 确认测试能准确失败、先写代码就重来、变异检查、mock 层级与完整性      |
| `diagnosing-bugs`       | 优先建立快速反馈、最小化问题、提出可证伪假设、添加调试日志     | 根因回溯、多层校验、条件等待、跨组件边界插桩、连续失败后重新检查架构 |
| `code-review`           | 从规范和规格两个维度并行评审、Fowler 代码坏味道基线            | 严重程度分级、评审者只读、无法核实项明确标记                         |
| `verifying-completion`  | 无                                                             | 声称完成前必须提供当前状态下的新鲜验证证据                           |
| `receiving-code-review` | 无                                                             | 先核实意见再实施，不做表面附和                                       |
| `finishing-a-branch`    | 无                                                             | 验证后由用户选择合并、创建 PR 或保留分支，并安全清理工作树           |
| `writing-for-agents`    | 上下文指针、信息层级、先导词、文档精简                         | 使用压力场景和子代理验证 skill，description 只描述触发条件           |

中文版本保留这些行为约束和设计意图，但不要求逐句对应英文原文。术语选择和表达方式遵循 [中文写作规范](./chinese-writing.md)。
