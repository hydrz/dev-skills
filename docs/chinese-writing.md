# 本仓库中文写作约定

通用的中文撰写、改写、翻译和审校方法见 [`writing-chinese`](../skills/writing-chinese/SKILL.md)。本文件只记录 dev-skills 仓库特有的读者、术语和格式约定。

编写 skill、`AGENTS.md` 或其他 agent 指令时，同时遵循 [`writing-for-agents`](../skills/writing-for-agents/SKILL.md)：先保证触发条件和行为语义正确，再审校中文表达。

## 目标读者与语气

- 默认读者是熟悉 Git、PR、API、TDD 等常见工程概念的中国大陆开发者，但不了解本项目的内部术语和上游背景。
- 使用专业、直接、协作的语气。强约束明确写出条件和结果，不依赖“无情”“拒绝”“裁决”等情绪或身份词强化。
- README 可以保留适量个性；skill 的执行步骤使用可以观察和验证的动作。

## 项目术语

- `CONTEXT.md` 只约束项目特有概念，不充当通用工程词典。
- 组件、服务、模块、API、签名和边界等词按各自原义使用。
- 抽象工作项称“任务”或“开发任务”；追踪器中的具体项目称 `issue`；运维、支持和审批场景才称“工单”。
- 不要求英文概念在所有场景使用同一个中文译词。先判断句子表达的行为，再选择自然说法。

常见场景：

| 英文概念              | 方案讨论               | 任务执行                 |
| --------------------- | ---------------------- | ------------------------ |
| frontier              | 当前待确认项           | 当前可执行任务、就绪任务 |
| blocking dependency   | 前置问题               | 前置依赖、任务依赖关系   |
| input/output relation | 依赖的信息、形成的结论 | 依赖或提供、输入或输出   |

## 技术词与格式

- 普通英文技术词使用小写：agent、skill、issue、diff、mock、schema。
- 固定缩写使用大写：PR、API、TDD、ADR、CI。
- 产品名、协议名和编程语言遵循官方写法。
- 命令、路径、文件名、字段、标签和代码标识使用行内代码。
- 中文引语使用全角引号“”。中文解释使用全角括号。
- 中文列举使用顿号、逗号或 Markdown 列表，不使用带空格的斜杠代替顿号。
- 中文与英文单词、数字之间加空格。中文与行内代码之间不强制加空格，同一文档保持一致。
- 标点使用逗号、冒号、句号和括号，不使用破折号。箭头只用于流程或状态转换。

## Skill 入口

- `name` 使用英文 kebab-case；正文和 description 使用中文。
- description 只说明触发场景，不概括正文步骤。
- 仅用户触发的 skill 说明用户在什么场景运行、产生什么结果，以及与相邻 skill 的区别。
- 可自动触发的 skill 写清独立的中英文触发分支，范围保持足够窄。

详细机制见 [`writing-for-agents/SKILL-MECHANICS.md`](../skills/writing-for-agents/SKILL-MECHANICS.md)。

## 上游内容本地化

修改上游 agent 指令时，先列出原文的触发条件、必须动作、边界、错误处理和完成条件。中文可以重新分段、换词和调整顺序，改写后逐项核对这些行为没有变化。

不要逐句翻译后再润色。先理解规则，再用中文重新表达。

## 仓库内的典型改写

| 不推荐                   | 推荐                                 |
| ------------------------ | ------------------------------------ |
| 被无情拷问一个计划或设计 | 逐轮澄清并压力测试一个计划或设计     |
| 按设计树逐轮处理前沿     | 每轮询问当前能够确认的全部决策       |
| 每张声明自己的阻塞边     | 每项任务明确列出前置依赖             |
| 台账扛过上下文压缩       | 将进度写入文件，以便上下文压缩后恢复 |
| 模型自主伸手去用它       | 模型在合适场景主动调用它             |
| 把迷雾毕业成新工单       | 将已经明确的问题拆成新的开发任务     |

## 修改检查

- 普通工程词是否被错误合并成项目术语？
- 相邻 skill 的边界是否无需打开正文就能理解？
- 中英文大小写、行内代码和中文标点是否一致？
- 重写前后的触发条件、行为约束和完成条件是否一致？
