实现用户在规格或开发任务中描述的工作。

1. **读清要求并商定接缝。** 阅读规格或任务的全文、验收标准与相关上下文。不重新推翻或展开新的方案讨论。规格或任务已写明测试层次和接缝时直接沿用；未写明时，先与用户商定测试接缝。

2. **准备工作区。** 当前位于 `main`、`master` 等主干分支时，先提示用户是否新建分支（或工作树）。用户选择工作树时，按 [WORKTREE.md](WORKTREE.md) 检测、创建并安装依赖；已经位于工作树中时不再新建。开始前运行一遍测试套件记录基线，基线失败时报告给用户。

3. **测试驱动构建。** 在商定的测试接缝上尽量使用 `tdd` skill，一次完成一个端到端最小闭环切片。频繁运行类型检查和单个测试文件，最后运行一次完整测试套件。

4. **代码评审。** 改动完成后使用 `code-review` skill 评审 diff（比较基准为你开始工作时的提交），使用 `receiving-code-review` skill 核实并处理评审意见。

5. **核对与提交。** 使用 `verifying-completion` skill 核对验收标准。把工作提交到当前分支，提交信息说明做了什么、为什么这样做。

6. **收尾。** 如果这是当前分支上的最后一项任务，提示用户使用 `finish-work` skill。
