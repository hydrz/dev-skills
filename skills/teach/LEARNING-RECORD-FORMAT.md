# 学习记录格式

学习记录放在 `./learning-records/`，按顺序编号：`0001-slug.md`、`0002-slug.md`。写第一条记录时再创建该目录。

学习记录相当于教学场景中的 ADR：记录不明显的收获、关键认识，以及用户说明的已有知识，用于指导之后的会话，并判断最近发展区。

## 模板

```md
# {学到或确认了什么的简短标题}

{1 到 3 句：学到了什么（或确认了哪些已有知识），以及它为什么会影响之后的会话。}
```

这就是全部格式。一条学习记录可以只有一段。它的价值在于记录*这项内容已经掌握*，以及*它为什么会改变接下来的教学内容*，而不在于填满各个小节。

## 可选小节

只在确实有价值时添加。大多数记录用不到。

- **状态** frontmatter（`active | superseded by LR-NNNN`）：早先的理解被证明有误并被替代时有用。
- **证据**：用户如何表现出理解（答对了问题、完成了练习、引用了过往经验）。结论可能被重新审视时有用。
- **影响**：这项收获让之后可以教什么，或不再需要教什么。不明显时值得写。

## 编号

扫描 `./learning-records/`，找到最大编号，加一。

## 何时写学习记录

满足以下任一条件时写：

1. **用户表现出对重要内容的真正理解**：不只是接触过，而是有证据表明能正确运用。这会提高后续教学的起点。
2. **用户说明了已有知识**：例如“我已经会 X 了”。记录下来，之后的会话就不再重复讲授。同时记录用户声称掌握的*程度*。
3. **纠正了一个误解**：用户之前相信某个错误说法，现在明白了为什么错。这类记录价值很高，能预判用户在相关主题上容易出错的地方。
4. **学习改变了学习目标**：用户发现自己真正关心的内容与原先设想的不同。交叉链接 [[MISSION.md]] 并更新它。

### 不需要记录的情况

- 只是讲过的内容。讲过不等于学会，要等有了证据再记录。
- 已经在 [[GLOSSARY.md]] 中以术语定义简洁记录过的内容。
- 每次会话的活动日志。学习记录是用于决策的认识，不是日记。

## 替代旧记录

新记录与旧记录矛盾时（用户理解加深或被纠正），把旧记录标为 `Status: superseded by LR-NNNN`，保留而不删除。理解如何变化的历史本身就是有用的信号。
