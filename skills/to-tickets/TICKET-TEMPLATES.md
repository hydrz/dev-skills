# 开发任务模板

按配置的追踪器类型选择对应模板。无论哪种形式，都不写代码文件路径或代码片段，它们很快会过时。依据文档（功能清单、设计依据、ADR、原型分支）必须链接。

例外：如果原型产出的片段（状态机、reducer、schema、类型结构）比文字更准确地表达了决策，内联它并简短注明来自原型。只截取表达决策的部分。

## 本地任务模板

适用于配置为本地 Markdown 文件的追踪器。每项任务一个文件，路径为 `.scratch/<功能-slug>/issues/<NN>-<slug>.md`。

```markdown
# <NN>：<任务标题>

Labels: ready-for-agent
State: open
Assignee: none
Blocked by: <前置任务编号，逗号分隔；没有时写 none>

**要构建什么：** 这项任务让哪段端到端行为可以工作。从用户视角描述，不写逐层实现清单。

**功能项：** <编号：状态，逗号分隔；例如 F-042：默认、支付中、已解锁>

**非功能需求：** <编号与目标值，没有时写“无”>

**测试：** <沿用规格测试决策中的测试层次、接缝和页面状态检查工具>

**依据文档：**

- <功能清单、设计依据、视觉规格章节、ADR、原型分支的链接>

**接口：**

- 依赖：<名称与结构，或“无”>
- 提供：<名称与结构，或“无”>

- [ ] F-042 默认：<可观察的行为>
- [ ] F-042 支付中：<可观察的行为>
- [ ] F-042 每个状态都有可以重复运行的自动化检查
- [ ] F-042 各状态截图与设计依据对比一致
```

## Issue 模板

适用于 GitHub、GitLab 等真实 issue 追踪器。

```markdown
## 父 issue

追踪器上父 issue 的引用（来源是已有 issue 时填写，否则省略本节）。

## 要构建什么

这项任务让哪段端到端行为可以工作。从用户视角描述，不写逐层实现。

## 功能项

<编号：状态，逗号分隔>

## 非功能需求

<编号与目标值，没有时写“无”>

## 测试

<沿用规格测试决策中的测试层次、接缝和页面状态检查工具>

## 依据文档

- <功能清单、设计依据、视觉规格章节、ADR、原型分支的链接>

## 接口

- 依赖：<名称与结构，或“无”>
- 提供：<名称与结构，或“无”>

## 验收标准

- [ ] <功能项编号和状态>：<可观察的行为>
- [ ] <页面类功能项>：每个状态都有可以重复运行的自动化检查
- [ ] <页面类功能项>：各状态截图与设计依据对比一致

## 前置依赖

- 每个前置任务的引用，或“无（可以立即开始）”。
```
