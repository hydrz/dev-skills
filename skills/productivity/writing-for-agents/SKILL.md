为 agent 写任何文档的参考：skill、`AGENTS.md` / `CLAUDE.md`、被指针指向的文档。包装不同，写法相同：同一组杠杆让文档变得可预测，也就是 agent 每次走同样的*过程*，而不是每次产出同样的结果。

- 写的是 skill 时，读 [SKILL-MECHANICS.md](SKILL-MECHANICS.md)，了解 frontmatter、调用方式和路由 skill。
- 写完一个约束纪律的 skill（会被 agent 以"就这一次"绕过的那种）要验证它是否管用时，读 [TESTING.md](TESTING.md)。

## 上下文指针

**上下文指针**（context pointer）是留在 agent 上下文里的一个引用，指向上下文外的某份材料，并写明去读它的条件。skill 的 description 是一种；`AGENTS.md` 里点名某份文档的一行字是同一种东西。决定 agent 何时去读、读得多可靠的，是指针的*措辞*，而不是它指向的内容。必读的材料挂在措辞很弱的指针后面，这是一个方差 bug：先把措辞磨尖，磨尖无效再把材料内联。

指针做两件事：说明材料是什么，列出应当触发去读它的**分支**（分支是文档处理的一种不同情况，不同的运行会走不同的路径）。常驻上下文的指针每个字每一轮都在付费，所以比正文更要狠剪：

- **先导词前置**：指针正是它发挥触发作用的地方。
- **一个分支一个触发词。** 给同一分支换个说法的同义词，是把一个分支写了两遍；合并，只留真正不同的分支。
- **正文已经说明的身份，从指针里删掉。**
- **只写何时用，不概括流程。** description 一旦概括了步骤，agent 会照着摘要走而跳过正文。

## 两种负载

每加一份文档或一个指针，都在花两种预算之一：

- **上下文负载**：常驻材料占用 agent 的窗口。`AGENTS.md` 的一行、skill 的 description，任何每轮都在上下文里的东西，无论是否触发都在花 token 和注意力。
- **认知负载**：人要记住有哪些文档、何时用哪个，人就是索引。这不是要最小化的成本，而是人类掌控权的代价：在需要人类判断的地方花，在不需要的地方拿掉。

只通过指针读到的材料，只付指针那一行的上下文负载；没有任何指针的材料，完全靠认知负载撑着。

## 信息层级

文档由两种内容构成：**步骤**（agent 按序执行的动作）和**参考**（按需查阅的定义、规则、事实）。二者可以自由混合：全是步骤（菜谱）、全是参考（评审规则、本 skill），或兼有。核心决策是把每一块放在**信息层级**的哪一级，层级按 agent 需要它的紧迫程度排列：

1. **文件内步骤**：首要一级，agent 按序做什么。
2. **文件内参考**：按需查阅。常常是合理的扁平并列集合（一次评审的所有规则放在同一级），这是正常的排列。
3. **披露出去的参考**：推到独立文件里，由上下文指针指向，指针触发时才加载。范围从同目录的兄弟文件，一直到放在任何地方、任何文档都能指向的外部参考。

往下推得太少，顶部臃肿；推得太多，又把 agent 真正需要的东西藏起来了。这个张力就是全部决策。

**渐进披露**是沿层级往下移（移出主文件，放到指针后面），让顶部保持清晰。它首先是保护层级的方式，其次才是省 token。分支是最干净的披露判据：所有分支都需要的内联，只有部分分支会走到的放到指针后面。文档有步骤时，本该披露的参考留在文件里会埋住步骤，让 agent 是否注意到步骤变成抛硬币：这是方差杠杆，不只是可读性问题。

**共置**是文件内的配套原则：层级决定一块内容放多深，共置决定放下之后旁边摆什么。把一个概念的定义、规则、注意事项放在同一个标题下，读到一部分就顺带读到它的邻居。检验：文档读起来应该像是专门写给 agent 的说明书。成组的材料读起来是这样，散落的不是。（这与重复不同：重复是同一含义出现在两处，散落是一个含义被拆到很多处。）

**蔓生**是这里的失败模式：文档就是太长，哪怕每一行都有效且不重复。注意力被多出来的部分摊薄，每多一行就多一行要保持相关。解药是层级：把参考披露到指针后面，按分支或按顺序拆分，让每条路径只带它需要的东西。

## 步骤与完成判据

每个步骤都以一个**完成判据**结束，也就是告诉 agent 这一步做完了的条件。它有两个属性，都是杠杆：

- **清晰度**：agent 能分辨做完和没做完吗？模糊的界限（"达成理解"）会诱发**过早完成**：步骤没真正做完就结束，注意力滑向*结束*本身。后面还看得见的步骤（**完成后步骤**）提供拉力，判据的清晰度提供阻力。按顺序防御：**先把界限磨尖**（局部、便宜）；只有它本质上无法磨尖、*并且*你确实观察到了抢跑，才通过拆分顺序把后续步骤藏起来。藏只有跨越真正的上下文边界才有效（交接或派发子代理；内联调用会把后续步骤留在上下文里，什么都没藏住）。
- **要求度**：它要求多少。"每个被修改的模型都有交代"能逼出彻底的工作，"列出变更清单"不能。要求度驱动**跑腿活**（agent 在工作中做的挖掘，潜藏在措辞里而非写成单独步骤），而且不局限于步骤："每条规则都用上了"约束一大片扁平参考，和"每一步都做完了"约束一串步骤一样，这就是纯参考文档也能带上穷尽要求的方式。

最强的判据既可检查又穷尽。

## 何时拆分

把一份文档拆成两份要花两种负载之一，所以只在切分划算时拆：

- **按顺序拆**：一串步骤里，完成后步骤诱使 agent 抢跑眼前这一步时拆开。让后续步骤不在视野里，能在当前任务上逼出更多跑腿活。反过来也要当心：合并顺序会把每一步的后续步骤暴露出来，诱发过早完成。
- **按调用方式拆**：skill 特有，见 [SKILL-MECHANICS.md](SKILL-MECHANICS.md)。

## 先导词

**先导词**（leading word）是模型预训练里已有的紧凑概念，agent 执行文档时用它来思考（_课_、_战争迷雾_、_曳光弹_）。它以词的形式反复出现，从不展开成句子，会累积出分布式的定义，用最少的 token 锚定一整片行为，因为它调用了模型本来就有的先验。自造新词也行，只要定义清楚，但生造的词没有先验可调：预训练词免费给的东西，你得用定义的 token 去买。先找现成的词。

它锚定两次。在正文里锚定*执行*：每次这个词出现，agent 都伸手去做同样的行为；在扁平参考里，它把注意力聚焦到一类要找的东西上。在指针里锚定*调用*：同一个词出现在你的提示、你的文档、你的代码库里，agent 就会把这套共享语言和材料联系起来，更可靠地读到它。

中文写作时，先导词首次出现附英文原词（"接缝（seam）"），同时调用中英文两套先验；优先采用经典译本里的译名（《程序员修炼之道》的"曳光弹"、《软件设计的哲学》的"深模块"、《修改代码的艺术》的"接缝"）。

主动寻找可以用先导词重构的地方。三个地方各展开一遍的三连描述，一个指针花一整句去比划一个概念。每一处都在等着被压缩成一个词：

- "快、确定、低开销" → _紧_（一个 _紧_ 的回路）
- "一个你信得过的回路" → _变红_，把模糊的关卡变成二值的可观察状态（回路在这个 bug 上变红，或者不变红）

两头都赢：token 更少，给 agent 挂靠思考的钩子更尖。默认每份文档都带着可以被先导词取代的重复表述，去找出来。

**否定**是这个杠杆旁边的失败模式：用禁令来引导，会把被禁止的行为拖进上下文，让它*更*容易被想到。_别想大象_，满脑子就只剩大象；否定是个弱修饰，被强烈激活的概念会压过它，禁令有一半被读成了去做那件事的指令。写**正向**的：直接说明目标行为（"注释写成一行"），被禁止的那个根本不出现。禁令只配留给无法正向表述的硬护栏；即便如此，也要配上正向目标，让注意力落在该做什么上。

## 修剪

- 每个含义只有**单一真相源**：一个权威位置，改行为只需改一处。**重复**（同一含义出现在多处）花维护成本和 token，还把这个含义在层级里的显著度抬得比实际更高。（它是先导词的意外反面：先导词是有意重复一个*词*，从不重复*含义*。）
- **环境**也是真相源（`package.json` 脚本、配置文件、目录结构、`--help` 输出），复述环境的文档就是一份**缓存**：一次查询结果的拷贝，只有查询代价高时才值得背负。缓存 agent 查不到的东西：没写下来的约定、选择背后的理由、配置不会坦白的坑。一个文件、一条命令就能查到的留给环境，那里不会过时。
- 逐行检查**相关性**：它还和文档要做的事有关吗？一行失去相关性，要么是它从来不影响任务（纯铺陈，或本该披露的分支），要么是它描述的行为或世界变了而它过时了。文档越短越容易保持相关。没有修剪纪律，默认的结局是**沉积**：过时的层层堆积，因为添加感觉安全、删除感觉危险，直到你得往下钻透好几层才找得到还有效的东西。
- 逐句找**无效指令**：模型默认就会遵守的指令，付了负载却什么也没说。判据（和默认行为相比，它改变行为了吗？）是相对模型的，不是相对读者的：两个人对某句是否无效有分歧，其实是对默认行为有分歧，要靠运行文档来解决，而不是争论。一句不合格就删整句，不要只删几个字。这个判据也检验先导词：一个弱到压不过默认行为的词（agent 本来就挺认真时写 _要认真_）是无效指令，修法是换更强的词（_无情地_），而不是换一种技巧。
