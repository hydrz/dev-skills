# MISSION.md 格式

`MISSION.md` 放在工作区根目录，记录用户学这个主题的*理由*。每个教学决策（下一步教什么、推荐哪些资源、设计什么练习）都要能追溯到这份文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1 到 3 句。用户在追求的具体现实目标：掌握这项技能后，他们的生活或工作会有什么改变？用底层结果代替"为了理解 X"这类抽象说法。}

## 成功的样子
- {一件用户将能做到的、具体可观察的事}
- {另一件}

## 约束
- {时间、预算、既有安排、学习偏好，任何限定做法的因素}

## 不在范围内
- {用户明确现在不想碰的相邻主题，用来保护最近发展区}
```

## 规则

- **一个工作区一个使命。** 想学两件无关的事，就是两个工作区。
- **具体胜过抽象。** "十月前跑完半马"胜过"变得更健康"；"给团队交付一个 Rust 命令行工具"胜过"学 Rust"。
- **追问含糊。** 用户说不清为什么，先拷问再落笔。坏使命比没有使命更糟。
- **现实变了就修订。** 目标移动了就更新本文件，让它始终指向当前的方向。
- **保持简短。** 超过一屏，它就不再是指南针，而成了计划。
