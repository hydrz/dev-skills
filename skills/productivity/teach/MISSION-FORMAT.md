# MISSION.md 格式

`MISSION.md` 放在工作区根目录，记录用户学习这个主题的*理由*。每个教学决策（下一步教什么、推荐哪些资源、设计什么练习）都要能追溯到这份文档。

## 模板

```md
# 学习目标：{主题}

## 为什么

{1 到 3 句。用户追求的具体现实目标：掌握这项技能后，用户的生活或工作会有什么变化？写出实际结果，而不是“为了理解 X”这类抽象说法。}

## 成功的标准

- {一件用户将能做到的、具体可观察的事}
- {另一件}

## 约束

- {时间、预算、已有安排、学习偏好，以及其他限制学习方式的因素}

## 不在范围内

- {用户明确表示暂时不想涉及的相关主题，用来让教学保持在最近发展区内}
```

## 规则

- **一个工作区一个学习目标。** 想学两件无关的事，就建两个工作区。
- **具体优于抽象。** “十月前跑完半程马拉松”优于“变得更健康”；“为团队交付一个 Rust 命令行工具”优于“学 Rust”。
- **澄清含糊的目标。** 用户说不清为什么想学时，先追问清楚再写。错误的学习目标比没有目标更糟。
- **现实变化时及时修订。** 目标发生变化时更新本文件，让它始终指向当前的方向。
- **保持简短。** 超过一屏时，它就不再是方向指引，而变成了学习计划。
