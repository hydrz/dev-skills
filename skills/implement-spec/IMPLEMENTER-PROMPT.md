# 实现者提示模板

派发实现者子代理时使用。方括号中的占位符由协调者填写。

```
子代理
  描述：“实现任务 [NN]：[任务标题]”
  能力等级：[按 SKILL.md 的能力选择；宿主支持覆盖模型或推理强度时显式设置]
  提示：|
    你负责实现任务 [NN]：[任务标题]。

    ## 需求与上下文

    - 需求：先读任务 [任务链接或路径]，其中的数值、名称和验收标准照原样使用。
    - 全局约束：[全局约束原文或指针，没有则写“无”]
    - 依据文档：[相关规格章节、设计依据或参考链接，没有则写“无”]
    - 前序进展：[已完成的相关模块、接缝或协调者决策，没有则写“无”]
    - 工作目录：[工作树路径]（分支 [分支名]，基于 [BASE]）

    ## 你的工作

    1. 实现任务描述的内容，严格满足验收标准。
    2. 在商定的接缝上使用 `tdd` skill，完成端到端最小闭环切片。
    3. 运行针对性的单元测试或集成测试，断言关键行为；提交前运行相关测试确保无回归。
    4. 提交你的工作。
    5. 自查并汇报。

    这项工作由你亲自完成，不派子代理。

    ## 能力不足或受阻时

    以下情况停下来，以 BLOCKED 或 NEEDS_CONTEXT 状态汇报，写清卡在哪里、试过什么、需要什么帮助：
    - 任务关键要求缺失或相互矛盾，按现有信息无法合理实现。
    - 任务需要在多个合理方案之间作架构取舍，或涉及缩减既定范围。
    - 遇到无法解决的外部依赖或环境故障。

    ## 汇报

    把完整报告写到 [报告文件路径]：
    - 实现了什么（受阻时写尝试了什么与阻塞原因）
    - 验证命令与测试结果

    向协调者回复简短状态：
    - **DONE**：已完成全部验收标准，测试全部通过并已提交。
    - **DONE_WITH_CONCERNS**：已完成并提交，但有架构或代码层面的观察顾虑（在报告中说明）。
    - **NEEDS_CONTEXT**：缺少关键上下文信息。
    - **BLOCKED**：受阻无法推进，已在报告中说明原因。
```
