# 每项任务一个 PR：依赖 PR 的处理

`implement-spec` 的按需参考：交付方式为每项任务一个 PR，并且存在依赖其他未合并 PR 的任务 PR 时读取。

## 前置任务的 PR 合并时

1. 合并前置任务的 PR，暂时保留它的分支。
2. 把依赖它的每个 PR 的目标分支改为主干，例如 `gh pr edit <编号> --base main`。
3. 所有依赖 PR 都改完后，再删除前置任务的分支。先删分支时，GitHub 会直接关闭依赖它的 PR，而且因为目标分支已不存在，PR 无法重新打开。
4. 把依赖分支变基到主干并推送，让 CI 运行。

合并由用户完成，所以创建依赖 PR 时就把这个顺序告诉用户，并提醒合并时不要勾选删除分支。

## CI 与目标分支

合并有依赖 PR 的任务 PR 时，遵循上一节的顺序：先把依赖 PR 的目标分支改为主干，再删除已合并的分支。

目标分支不是主干的 PR 可能从未运行 CI（例如 CI 只对指向主干的 PR 触发），而只用 `gh pr edit --base` 改目标分支也不会触发 CI。改完目标分支后，推送变基后的分支，或关闭再重新打开 PR，让 CI 在主干上运行；等 CI 通过后，才把这个 PR 视为可以合并。
