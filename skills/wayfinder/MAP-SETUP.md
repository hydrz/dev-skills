# 建立地图与补建功能清单

`wayfinder` 的按需参考：用户带着松散的想法调用（建立地图），或已有地图、规格、任务但缺少功能清单时（补建功能清单）读取。决策项类型、尚未明确和不在范围内的定义见主文件。

## 建立地图

用户带着一个松散的想法调用。

1. **确定目标。** 分别使用 `grilling` 和 `domain-modeling` skill，确定这张地图要找到路径的对象：规格、决定还是改动。目标决定范围，所以先确定它。
2. **梳理当前可处理的问题。** 再追问一轮，这次**先求广度**：覆盖整个问题空间，而不是在某一条线上深挖，找出悬而未决的决定和现在就能迈出的第一步。**如果这一步没有发现尚未明确的问题**（通往目标的路径已经清晰，整项工作一个会话就能完成），就不需要地图。停下来，询问用户想如何继续。
3. **起草功能清单**（目标需要功能清单时）。按“角色 × 端 × 页面或功能”逐格过一遍，把能想到的功能项全部列出，每项先写名称、类型、角色和端。已有产品文档（页面地图、需求文档、旧规格、竞品截图）时，先从中提取，再补全。暂时说不清需覆盖状态或设计依据的功能项，结论写“待定”，之后为它们建决策项。把清单交给用户过目，功能项的增删和每项的发布批次都由用户确认。

   同时列出非功能需求（性能、无障碍、多语言、可观测性）的候选项。还没有目标值的，写进**尚未明确**。

4. **创建地图**（标签 `wayfinder:map`）：填写目标和备注，“已做决策”留空，把尚未明确的问题写进**尚未明确**。
5. **创建现在能描述清楚的决策项**，作为地图的子 issue。然后**另起一遍**建立依赖关系，因为 issue 要先有 id 才能互相引用。建立依赖后，决策项分为可领取和被阻塞两类；还无法描述清楚的问题留在**尚未明确**一节。结论为“待定”的功能项，要么已被某个决策项覆盖，要么写进**尚未明确**。
6. **派出调研子代理。** 为刚创建的每个 `research` 决策项派一个子代理并行处理，子代理使用 `research` skill。结论保存在一次性的 `research/<名称>` 分支上，并在决策项中留下上下文指针。
7. 停止。建立地图是一个会话的工作，不在本会话中亲自解决任何决策项。

## 补建功能清单

已有地图、规格或任务，但缺少功能清单时（例如 `/to-spec` 因此停下，让用户运行本 skill），用这个模式：

1. 读取已有的地图、规格、任务、产品文档和设计资料。
2. 按“建立地图”第 3 步起草功能清单，并对照已有任务标出缺口：没有任务覆盖的功能项、只覆盖部分状态的功能项、没有设计依据的页面。
3. 把清单和缺口交给用户确认。
4. 没有地图时新建地图；已有地图时在备注中链接清单。把缺口转成决策项：缺设计依据的写成 `design`，缺行为决定的写成 `grilling` 或 `research`。
5. 停止。缺口由后续“推进地图”的会话逐个解决。
