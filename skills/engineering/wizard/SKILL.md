# 向导

**向导**是一个 bash 脚本，一步步带人走完一个手动流程：这种流程手动做很烦，每次重新给 AI 解释也很烦。它打开每个 URL，说清楚点哪里、复制什么，抓取值，写到该去的地方（`.env`、GitHub secrets），每个阶段都确认，并显示还剩几个阶段。它可能是配置第三方服务、执行一次性迁移，或把项目从一个状态迁到另一个状态。

好用的交互体验 [template.sh](template.sh) 已经解决了：分阶段进度、确认闸门、跨平台打开 URL（包括 WSL）、隐藏输入密钥、幂等写入 `.env`、`gh secret` / `gh variable` 写入、结束时的汇总。**你的工作只是界定流程并编写它的各个阶段。** `STAGES` 标记之上的库在每个向导里都一模一样，这种一致性正是意义所在：库代码保持原样，只编辑标记之下的部分。

向导默认是一次性的：为一次运行而写，存到临时目录或 `scripts/`，事情做完就删。只有用户想要一条应该留在仓库里、可重复的配置路径时才提交。

## 过程

### 1. 界定流程

弄清人必须做的每个手动步骤，以及沿途要抓取的每个值。先读仓库，别冷启动就问：

- 配置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 迁移或切换类：当前状态、目标状态，以及二者之间不可逆的操作。

然后把阶段的顺序清单和每个阶段产出的值给用户看并确认：他们可能增加、删除或调整顺序。

**完成判据：** 每个阶段都按顺序命名了；对每个要抓取的值，你知道 (a) 人从哪里拿到它，(b) 它写到哪里（`.env`、GitHub secret、两者都写，或都不写；有些阶段是纯操作），(c) 它是否是密钥（隐藏输入）。

### 2. 描出每个阶段的路径

为每个阶段写出人要走的精确路径：打开哪个 URL、在那里做什么、值显示在哪、填哪个变量。比如"控制台 → 开发者 → API 密钥 → 显示测试密钥 → 复制"。你并不确切知道当前 UI 或确切命令时，直说，问用户或查文档：每一步都要能在真实界面里找到。

**完成判据：** 每个阶段都对应到陌生人也能照做的具体指示。

### 3. 编写向导

把 `template.sh` 复制到目标路径。把示例阶段替换成每步一个 `stage`，按依赖顺序排列。使用库里的辅助函数：`stage`、`say` / `step`、`open_url`、`ask` / `ask_secret`、`write_env`、`set_secret` / `set_var`、`pause` / `confirm`。把 `TOTAL_STAGES` 设为你写的阶段数。

守住模板设定的标准：先打开 URL 再要值；密钥一律用 `ask_secret`；每个需要持久化的值都 `write_env`；只 `set_secret` CI 真正需要的值；任何不可逆操作之前 `confirm`。每个 `stage` 会清屏，只显示当前步骤：一个阶段只做一件聚焦的事，人需要看的内容就不会滚出屏幕。

### 4. 验证并交付

- `bash -n <脚本>`；有 `shellcheck` 就跑一下。
- `chmod +x <脚本>`。
- 端到端运行交给人：它会打开浏览器并阻塞等待人的输入。你做静态追踪：第 1 步的每个值都被抓取，并落到第 1 步说的位置；每个 `set_secret` 的名字与 CI 里的 `secrets.*` 引用完全一致。
- 告诉用户怎么运行。它是可重复的配置路径时，提交并在 README 里链接，下一个人直接运行脚本，而不是去问 AI。
