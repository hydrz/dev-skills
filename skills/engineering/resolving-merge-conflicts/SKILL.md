---
name: resolving-merge-conflicts
description: 根据冲突两侧的改动意图解决正在进行的 Git merge 或 rebase。用于“解决合并冲突、resolve conflicts、继续 rebase”等请求。
---

1. **看清现状。** 查看 merge / rebase 的当前状态、git 历史和冲突文件。

2. **找到每处冲突的一手资料。** 深入理解每一侧的改动为什么存在、原本意图是什么。读提交信息，查 PR，查源头 issue 或工单。

3. **逐个 hunk 解决。** 尽量保留两侧的意图。二者不兼容时，选与这次合并的既定目标一致的那一侧，并写明取舍。只组合两侧已有的行为，不发明新行为。始终把冲突解决掉，`--abort` 不在选项里。

4. **跑自动化检查。** 找出项目的检查命令并运行，通常依次是类型检查、测试、格式化。修掉合并弄坏的东西。

5. **完成 merge / rebase。** 暂存全部改动并提交。rebase 时继续推进，直到所有提交都变基完成。

完成之前遵循 `verifying-completion`：检查命令的输出是本轮跑出来的。
