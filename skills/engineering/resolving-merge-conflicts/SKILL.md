---
name: resolving-merge-conflicts
description: 根据冲突两侧的改动意图解决正在进行的 Git merge 或 rebase。用于“解决合并冲突、resolve conflicts、继续 rebase”等请求。
---

1. **了解现状。** 查看 merge 或 rebase 的当前状态、git 历史和冲突文件。

2. **找到每处冲突的一手资料。** 深入理解每一侧的改动为什么存在、原本的意图是什么。阅读提交信息，查看 PR，查找来源 issue 或开发任务。

3. **逐个 hunk 解决。** 尽量保留两侧的意图。两者不兼容时，选择与本次合并既定目标一致的一侧，并写明取舍。只组合两侧已有的行为，不引入新行为。始终完成冲突解决，不使用 `--abort`。

4. **运行自动化检查。** 找出项目的检查命令并运行，通常依次是类型检查、测试、格式化。修复合并引入的问题。

5. **完成 merge 或 rebase。** 暂存全部改动并提交。rebase 时继续执行，直到所有提交都完成变基。

完成之前遵循 `verifying-completion`：检查命令的输出必须来自本轮运行。
