# 阶段边界

**阶段**是会话中的一段工作，例如追问、实现、QA。这个定义刻意保持宽松：当你觉得“好，这部分完成了”，一个阶段就结束了。

**阶段边界**是两个阶段之间的间隙，也是作出下面这个决定的唯一时机。阶段中途不作这个决定：要么继续，要么把剩余工作交给子代理。阶段中途压缩上下文，会让 agent 丢失工作线索。

## 五个选项

| 选项 | 做什么 |
|---|---|
| **继续** | 留在当前会话，不切换上下文 |
| **`/clear`** | 清空上下文窗口，从零开始 |
| **`/handoff`** | 写一份可移植的 Markdown 文件，可以在任何地方用它开启会话 |
| **子代理** | 把任务放进独立的上下文窗口，拿回一份报告 |
| **`/compact`** | 压缩当前上下文，用摘要开启新会话 |

## 判断顺序

在边界上从第一个问题开始依次判断，第一个回答为**是**的问题决定选项。

**1. 能在当前会话中继续吗？** 满足以下任一条件时，回答为是：

- 下一阶段需要把当前阶段作为**一手资料**；
- 模型仍能可靠推理，剩余上下文足以容纳下一阶段。

判断后者时，留意这些信号：上下文已经接近上限、难以准确回忆早期决策、输出开始遗漏已经确认的约束。出现这些信号时，回答为否。

从追问进入实现是典型的“是”：实现需要原始的推理过程，而不是它的摘要。继续没有成本，也不丢失信息，所以先判断它，再考虑其他选项。

**2. 当前上下文与后续工作无关吗？** 如果会话中的全部内容（探索、决策、走不通的尝试）都可以丢弃，选择 **`/clear`**。这是成本最低的选项：不花时间，并释放整个上下文窗口。`/clear` 之后旧会话仍然可以恢复。

判断错误的代价并不对称。清空了*相关*的上下文，就会丢失已完成工作背后的**原因**，读再多遍 diff 也无法找回。

**3. 需要交接吗？** `/handoff` 的用途很窄，只适用于以下情况：

- 切换到**另一个 agent 工具**（例如从 Claude Code 切到 Codex）；
- 切换到**另一个目录**或仓库；
- 把工作交给**同事**；
- 在**阶段中途**发现一个旁支任务，想分出去处理，又不打断当前工作。

以上就是全部适用条件。`/handoff` 提供的是**可移植性**：一个可以带走的文件。没有需要带走的内容时，就不需要它。

**4. 这个任务能在无人值守的情况下完成吗？** 如果任务范围足够明确，你离开后无需指导也能完成，把它交给**子代理**，当前会话保持不变。自动化评审是典型情况：agent 阅读 diff、撰写报告，这期间不需要你参与。

**5. 以上都不是时，使用 `/compact`。** 上下文与后续相关、使用同一个 agent 工具、在同一个目录、你需要持续参与：这种情况会走到这一步，而且很常见。给它一句说明（例如 `/compact 接下来要对这部分做 QA`），让摘要保留下一阶段需要的信息。

`/compact` 是**默认选项，不是第一反应**。它排在最后，因为前四个选项要么成本更低，要么更精确。一开始就使用它的典型失败是：新会话基于被摘要丢失细节的决策，自信地做出错误判断。

## 一手资料与二手资料

除了**继续**，其他选项都会把**一手资料**变成**二手资料**：会话的原始内容被摘要取代。两者的取舍总是相同：

| 来源 | 信息 | 噪音 | 剩余空间 |
|---|---|---|---|
| 一手资料（继续） | 完整 | 多 | 小 |
| 二手资料（`/compact`、`/handoff`） | 有损失 | 少 | 大 |

这就是第 1 个问题排在最前面的原因。只有留在当前会话的代价超过它带来的好处时，才接受信息损失。

## 这些都需要判断

这些问题没有客观答案：每个都依赖经验判断，同一个边界在不同情况下可能得出不同结论。它们的价值在于**按顺序**提问，并且在边界上而不是工作中途提问。
