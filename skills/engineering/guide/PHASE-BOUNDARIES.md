# 阶段边界

**阶段**是会话里的一段工作：拷问、实现、QA。这个定义刻意模糊：当你想"好，这部分搞定了"，一个阶段就结束了。

**阶段边界**是两个阶段之间的间隙，也是这个决定唯一该出现的地方。阶段中途没有决定要做：继续，或者把剩下的工作拆给子代理。阶段中途压缩会让 agent 丢掉线索。

## 五个选项

| 选项 | 做什么 |
|---|---|
| **继续** | 留在会话里，完全不切换上下文 |
| **`/clear`** | 清空上下文窗口，从零开始 |
| **`/handoff`** | 写一份可移植的 Markdown 文件，在任何地方用它开启会话 |
| **子代理** | 把任务送进它自己的上下文窗口，拿回一份报告 |
| **`/compact`** | 压缩当前上下文，用摘要开启一个新会话 |

## 决策树

在边界上从上往下走。第一个**是**胜出。

**1. 能在这个会话里继续吗？** 两件事让答案为是：下一阶段需要把这个阶段当作**一手资料**，或者你还剩足够的**智能区**（约 15 万 token）装下下一阶段。拷问 → 实现是标准的"是"：实现要的是原汁原味的推理，而不是它的摘要。继续不花代价、不丢东西，所以先把它排除掉，再考虑别的。

**2. 上下文与接下来的事无关吗？** 这个会话里的一切（探索、决定、死胡同）都可以丢吗？是的话，**`/clear`**。这是棋盘上最便宜的一步：不花时间，把整个窗口还给你。`/clear` 也不是终点：旧会话仍然可以恢复。

判断错的代价是单向的。清空一个*相关*的上下文，你就丢掉了所建之物背后的**为什么**，把 diff 读多少遍都拿不回来。

**3. 需要交接吗？** `/handoff` 的用途很窄。只在以下情况需要：

- 换到**新的 harness**（Claude Code → Codex），
- 移到**新的目录**或仓库，
- 把工作交给**同事**，
- 或者在**阶段中途**发现一个旁支任务，想分出去又不打断手头的事。

这张清单就是全部条件。`/handoff` 换来的是**可移植性**：一个能带走的文件。没有东西要带走，就不需要它。

**4. 这个任务能离席完成吗？** 它的范围是否紧凑到你离开键盘、无需引导也能跑完？是的话，把它交给一个**子代理**，这个会话保持不动。自动化评审是标准情况：agent 读 diff、写报告，这期间不需要你。

**5. 否则，`/compact`。** 上下文相关、同一个 harness、同一个目录、你需要留在回路里：决策树落在这里，而且经常落在这里。给它一句指示（`/compact 接下来要对这块做 QA`），让摘要保留下一阶段需要的东西。

`/compact` 是**默认项，不是第一反应**。它在最底部，因为上面四个问题都更便宜或更精确。一上来就用它的失败模式是：新会话对一个被摘要抹平了的决定充满自信地弄错。

## 一手资料与二手资料

除了**继续**，每一步都把**一手资料**变成**二手资料**：会话本来的样子，被它的摘要取代。这笔交易的形状总是一样的：

| 来源 | 信息 | 噪音 | 腾挪空间 |
|---|---|---|---|
| 一手（继续） | 完整 | 多 | 小 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 大 |

这就是问题 1 排在最前面的原因。只有当留下来的代价超过它省下的时，才去付这份有损。

## 这些都是判断题

这些问题不是客观的：每个都带着品味，同一个边界在不同的日子可能走向不同。价值在于**按顺序**问它们，并且在边界上问，而不是在工作中途问。
