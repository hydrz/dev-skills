# 先证据后结论

声称任何状态之前，先拿到**新鲜证据**：本轮运行过证明它的命令，并读过输出。

这条规则约束的是含义，不是措辞：换个说法（"应该好了""看起来没问题""搞定"）表达的仍是完成声明，同样需要证据。

## 闸门

```
声称任何状态、或表达满意之前：

1. 确定：什么命令能证明这个说法？
2. 运行：完整地、重新地运行它
3. 阅读：完整输出，检查退出码，数失败数
4. 核对：输出支持这个说法吗？
   - 不支持：陈述真实状态，附上证据
   - 支持：陈述结论，附上证据
5. 然后才说出结论
```

## 什么证据证明什么

| 说法 | 需要的证据 | 不够的 |
|---|---|---|
| 测试通过 | 测试命令输出：0 失败 | 之前某次运行、"应该能过" |
| lint 干净 | lint 输出：0 错误 | 部分检查、推断 |
| 构建成功 | 构建命令：退出码 0 | lint 通过、日志看着正常 |
| bug 修好了 | 复现原始症状的回路：现在变绿 | 代码改了、以为修好了 |
| 回归测试有效 | 红绿循环：撤掉修复会变红，恢复后变绿 | 测试跑通过一次 |
| 子代理完成了 | VCS diff 显示了预期的改动，关键命令你自己重跑过 | 子代理报告"成功" |
| 需求满足 | 逐条对照规格或工单的核对清单 | 测试全过 |

## 常用模式

**回归测试（红绿验证）：**

```
✅ 写测试 → 运行（通过）→ 撤掉修复 → 运行（必须失败）→ 恢复修复 → 运行（通过）
❌ "我写了一个回归测试"（没做红绿验证）
```

**需求：**

```
✅ 重读规格 → 建核对清单 → 逐条核对 → 报告缺口或完成
❌ "测试都过了，这一阶段完成"
```

**委派：**

```
✅ 子代理报告成功 → 看 diff → 核对改动 → 报告实际状态
❌ 直接转述子代理的报告
```

## 表述

- 有证据：直接陈述结论并附上证据，"`pnpm test`：142 通过，0 失败"。
- 证据不足：说明你验证了什么、没验证什么，"单测已跑且通过；端到端测试需要浏览器，本环境无法运行"。
- 证据相反：陈述真实状态，"3 个测试仍然失败，输出如下"。

## 借口与事实

| 借口 | 事实 |
|---|---|
| "应该没问题了" | 运行验证命令 |
| "我很有把握" | 把握不是证据 |
| "lint 过了" | lint 不检查编译，跑构建 |
| "子代理说成功了" | 独立核对 diff 和命令输出 |
| "刚才跑过了" | 刚才的运行只证明刚才的代码树，对当前的树重跑 |
| "只查一部分就够了" | 部分检查只证明那一部分，把范围说清楚 |
