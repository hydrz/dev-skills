# 范围清单

范围清单列出一项工作要交付的全部范围项。规格、开发任务、实现和验收都通过范围项编号引用它，所以它同时是覆盖矩阵：从清单能直接看出每个范围项由哪份规格负责、由哪些任务实现。

## 什么时候需要

- **大型工作**（`/wayfinder` 开启的工作，或需要拆成规格集的工作）：建立独立的清单文件。
- **小功能**（一份规格就能描述）：在规格的“范围项”一节使用同样的列，不建独立文件。

## 位置

- 清单：`docs/scope/<工作-slug>.md`
- 设计资料（设计稿导出、选定原型变体的截图）：`docs/scope/design/<工作-slug>/`，文件名以范围项编号开头，例如 `S-042-锁定.png`

多上下文仓库放在对应上下文的 `docs/scope/` 下。跨上下文的工作放在根目录的 `docs/scope/`。

## 文件结构

```markdown
# <工作名称> 范围清单

目标：<一两行，与地图或规格的目标一致>

## 规格集

| 规格               | 业务模块 | 范围项         | 前置规格 | 状态   |
| ------------------ | -------- | -------------- | -------- | ------ |
| [<规格标题>](链接) | <模块>   | S-001 至 S-018 | 无       | 已发布 |

## 范围项

| 编号  | 类型         | 名称             | 角色 | 端               | 状态集                               | 设计依据                               | 规格   | 任务                                               | 处置 |
| ----- | ------------ | ---------------- | ---- | ---------------- | ------------------------------------ | -------------------------------------- | ------ | -------------------------------------------------- | ---- |
| S-042 | 界面（关键） | 锁定剧集解锁面板 | 观众 | iOS、Android、H5 | 默认、余额不足、支付中、失败、已解锁 | [设计稿](design/actoya/S-042-默认.png) | 商业化 | T09（默认、支付中、已解锁）、T11（余额不足、失败） | 已定 |

## 不在范围内

- S-050 <名称>：<原因>。确认人：<用户>，<日期>
```

规格集只有一份规格时，“规格集”一节只写一行。

## 字段

- **编号**：`S-` 加三位数字，创建后不再改变，也不复用。
- **类型**：`界面（关键）`、`界面（常规）`、`能力`、`作业`、`集成`。关键界面指首屏、转化路径和核心体验；其余界面为常规界面。
- **名称**：使用 `CONTEXT.md` 中的词。
- **角色、端**：这个范围项适用的全部角色和客户端。同一界面在不同端的表现差异很大时，拆成多个范围项。
- **状态集**：必须覆盖的全部状态。只实现默认状态不算完成。常用起点：
  - 界面：默认、加载、空、错误、无权限，再按业务补充（锁定、离线、超长文案、多语言）。
  - 能力和集成：成功、校验失败、重复请求、外部服务失败、撤销或退款。
  - 作业：成功、重试、失败进入死信、重放。
- **设计依据**：链接到事实来源。
  - 关键界面：设计稿、选定的原型变体截图，或视觉规格的具体章节。
  - 常规界面：可以写一条决定，“按设计系统实现，参照 <具体界面或范围项编号>”。只写“按设计系统”不算设计依据。
  - 能力、作业、集成：链接到行为决策（规格章节、ADR、决策项或逻辑原型）。
- **规格**：规格集中负责它的那份规格。
- **任务**：由 `/to-tickets` 回填，写明每项任务覆盖哪些状态。
- **处置**：`待定`、`已定` 或 `不在范围内`。

## 规则

- **扩大范围可以直接做。** 新增范围项或补充状态时，写入清单并在对应规格或进度记录中说明来源。
- **缩减范围必须由用户确认。** 把范围项改为“不在范围内”、删除状态、降低设计依据要求，都要先得到用户明确同意，并在“不在范围内”一节写明确认人和日期。agent 不能以代行决策的方式缩减范围。
- **“已定”的前提。** 状态集已填写，设计依据满足上面的要求。
- **拆分信号。** 一份规格负责的范围项超过约 25 个时，考虑拆分规格；一项任务覆盖的范围项超过 5 个时，考虑拆分任务。
