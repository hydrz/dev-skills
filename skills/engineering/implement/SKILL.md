实现用户在规格或工单里描述的工作。

1. **读清要求。** 读规格或工单的全文和评论，以及它们引用的全局约束。有疑问或发现要求之间有冲突，动手之前先问。规格没有明确约定测试接缝的，先和用户确认接缝。

2. **准备工作区。** 当前在 `main` / `master` 等主干分支上时，先问用户是否新建分支（或工作树）。开始前跑一遍测试套件，记下基线：基线就是红的，报告出来并问用户是否继续。

3. **构建。** 在事先约定的接缝上尽量用 TDD：调用 Skill 工具，参数为 `tdd`。一次一个垂直切片。

   经常跑类型检查，经常跑单个测试文件，最后跑一次完整测试套件。

4. **评审。** 调用 Skill 工具，参数为 `code-review`，固定点是你开始时的提交。处理评审意见：调用 Skill 工具，参数为 `receiving-code-review`。

5. **核对完成。** 调用 Skill 工具，参数为 `verifying-completion`。逐条对照验收标准，每条都要有本轮跑出来的证据。

6. **提交。** 把工作提交到当前分支。提交信息说明做了什么、为什么。

7. **收尾。** 这是一个分支上的最后一项工作时，调用 Skill 工具，参数为 `finishing-a-branch`。
