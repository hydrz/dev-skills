实现用户在规格或开发任务中描述的工作。

1. **读清要求。** 读规格或任务的全文和评论，以及它们引用的全局约束。有疑问或发现要求互相冲突时，先问清楚再动手。规格没有明确测试接缝时，先和用户确认接缝。

2. **准备工作区。** 当前位于 `main`、`master` 等主干分支时，先问用户是否新建分支（或工作树）。开始前运行一遍测试套件，记录基线。如果基线已经失败，报告给用户并询问是否继续。

3. **构建。** 在事先约定的接缝上尽量使用 TDD：调用 Skill 工具，参数为 `tdd`。一次完成一个端到端最小闭环。

   频繁运行类型检查和单个测试文件，最后运行一次完整测试套件。

4. **评审。** 调用 Skill 工具，参数为 `code-review`，比较基准是你开始工作时的提交。处理评审意见时，调用 Skill 工具，参数为 `receiving-code-review`。

5. **核对完成。** 调用 Skill 工具，参数为 `verifying-completion`。逐条对照验收标准，每条都要有本轮运行得到的证据。

6. **提交。** 把工作提交到当前分支。提交信息说明做了什么、为什么这样做。

7. **收尾。** 如果这是当前分支上的最后一项工作，调用 Skill 工具，参数为 `finishing-a-branch`。
