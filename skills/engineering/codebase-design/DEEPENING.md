# 加深

给定依赖情况，如何安全地把一簇浅模块加深。沿用 [SKILL.md](SKILL.md) 里的词汇：**模块**、**接口**、**接缝**、**适配器**。

## 依赖分类

评估一个加深候选时，给它的依赖分类。类别决定加深后的模块如何跨接缝测试。

### 1. 进程内

纯计算、内存状态、无 I/O。总是可以加深：合并模块，直接通过新接口测试。不需要适配器。

### 2. 本地可替身

有本地测试替身的依赖（Postgres 用 PGLite、内存文件系统）。替身存在就可以加深。加深后的模块在测试套件里跑着替身来测。接缝在内部，模块外部接口上没有端口。

### 3. 远程但自有（端口与适配器）

跨网络边界的自有服务（微服务、内部 API）。在接缝处定义一个**端口**（接口）。深模块拥有逻辑，传输作为**适配器**注入。测试用内存适配器，生产用 HTTP / gRPC / 队列适配器。

建议的说法：*"在接缝处定义端口，生产用 HTTP 适配器、测试用内存适配器，这样即便部署跨网络，逻辑也集中在一个深模块里。"*

### 4. 真正的外部依赖（Mock）

你控制不了的第三方服务（Stripe、短信平台等）。加深后的模块把外部依赖作为注入的端口接收，测试提供 mock 适配器。

## 接缝纪律

- **一个适配器是假想的接缝，两个适配器才是真的。** 至少有两个站得住的适配器（通常是生产 + 测试）时才引入端口。只有一个适配器的接缝只是多了一层间接。
- **内部接缝与外部接缝。** 深模块可以有内部接缝（实现私有，供自己的测试用），也有接口处的外部接缝。测试用到的内部接缝留在内部，不必因此暴露到接口上。

## 测试策略：替换，而非叠加

- 加深后模块的接口上有了测试，浅模块上的旧单元测试就成了浪费，删掉。
- 在加深后模块的接口上写新测试。**接口就是测试面。**
- 测试通过接口断言可观察的结果，不断言内部状态。
- 测试描述的是行为而非实现，所以应当扛得住内部重构。实现一变测试就得改，说明它越过了接口。
