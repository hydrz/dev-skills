# 台账格式

台账是 `implement-spec` 写在磁盘上的进度文件。对话记忆扛不过上下文压缩；丢了位置的协调者会把已完成的工单整串重派，这是最昂贵的失败。台账和 `git log` 才是恢复现场的依据。

## 位置

`<仓库根>/.dev-skills/implement-spec/<规格-slug>/`

这个目录归这一份规格所有：台账、实现者报告、评审包都放在这里。其他规格的目录不读不写。确保 `.dev-skills/` 在 `.gitignore` 里。`git clean -fdx` 会删掉它；那时从 `git log` 和追踪器上的工单状态恢复。

## 文件：`ledger.md`

第一行是身份，其余按时间顺序只追加。

```markdown
# implement-spec 台账 · 规格：<规格链接或路径>

集成分支：<分支名> · 起点：<sha7> · PR：<链接或"仅本地">

## 预检

| 对象 | 检查内容 | 结果 | 裁决 |
|---|---|---|---|
| 工单 02 ↔ 工单 04 | 02 产出 `parseOrder(raw): Order`，04 消费 `parseOrder(input): Order \| null` | 返回类型不一致 | 裁决：以规格"非法输入返回错误结果"为准，统一为 `Order \| null` \| 理由：规格用户故事 7 \| 错了的代价：04 需改一处调用 |
| 工单 03 | 验收标准与"要构建什么"是否自洽 | 自洽 | 无 |

## 进度

- 工单 01：派发（BASE a1b2c3d，模型：便宜档，工作树 .worktrees/ticket-01）
- 工单 01：完成（提交 a1b2c3d..d4e5f6a，评审通过）
- 工单 02：修复第 1/3 轮（已解决 2，未解决 0；提交 d4e5f6a..b7c8d9e）
- 工单 02：次要（延后）：错误信息未包含订单号
- 工单 02：完成（提交 d4e5f6a..b7c8d9e，评审通过）
- 工单 05：搁置：评审认为应缓存汇率 | 裁决：规格要求实时汇率，保持现状 | 错了的代价：高并发下多一次外部调用
```

## 恢复规则

- 有 `工单 NN：完成` 行的工单已经完成，不再派发。
- 某张工单最后一行是修复轮次，说明它在循环中途：从下一轮继续。
- 最后一行是"派发"但没有后续：检查该工单分支的提交和报告文件，再决定是继续评审还是重新派发。
- 台账与你的记忆不一致时，信台账和 `git log`。
