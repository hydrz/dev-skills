# 中文写作与审校

让目标读者能够顺畅找到结论、理解依据，并知道接下来要做什么。清楚不等于口语化或篇幅短；保留内容所需的专业性、细节和语气。

## 规则顺序

发生冲突时依次遵循：

1. 用户明确提出的要求；
2. 内容所属项目或组织的约定；
3. 对应文体和专业领域的规范；
4. 通用中文规范；
5. 本 skill 的默认风格。

处理法律文本、正式公文、UI 文案、营销文案等专业内容时，让对应领域规则决定内容和格式；本 skill 负责中文表达的清晰度、自然度和语义保真。

## 写作阶段与关注点

中文写作分为两个截然不同的阶段，避免在探索期过早挑剔文字，或在收敛期留下未铺垫的认知断层：

- **探索阶段（从零构思）**：关注可能性的发掘与原材料积累。不必过早确定章节结构或润色词句，重点是收集构思素材（核心断言、案例、代码片段、真实痛点）、提炼支撑整篇叙事的关键承重词（leading word），并盘点读者走进文章时已知的前提集合。交付物是零散但高价值的构思素材与候选切入起笔方向。
- **收敛阶段（步调推进与审校）**：关注论据咬合与成文交付。锁定行文主线，将前期素材按需取用与裁剪，步步为营推进；严格遵循“认知铺垫（Grounding，先铺垫后引用）”法则——未在前置论述中明确铺垫的概念，严禁在后续论证中突兀作为论据引用。交付物是逻辑自洽、排版规范的成稿或带证据的审校建议。

## 动笔之前

从请求和材料中确定以下信息，不必默认展示分析过程：

- 目标读者已知什么（作为读者自带的前置认知），还不知道什么；
- 这份内容要解决什么问题、核心论断与承重词是什么；
- 读者最需要记住的结论；
- 读完后需要作出什么判断或行动；
- 用户或原文使用的是简体还是繁体中文。

可以从上下文可靠推断时直接继续。缺失信息会显著改变术语、背景、语气或内容时，先向用户确认。没有中文变体线索时，使用中国大陆简体中文；已有原文时保持原文使用的变体。

改写或翻译已有内容时，先提取必须保留的事实、条件、约束、承诺、不确定性和语气。处理 skill、`AGENTS.md`、`CLAUDE.md` 或其他 agent 指令时，先使用 `writing-for-agents` skill 保证指令结构和行为正确，再审校中文表达。

## 按请求交付

- **构思**：探索阶段。通过梳理或追问挖掘构思素材，确定读者前置认知基线，提炼承重词，并给出 2 到 3 个候选切入视角（起笔方向），不强求过早成稿。
- **撰写**：收敛阶段。以最小论述单元为步进，严格遵循先铺垫后引用的认知铺垫原则，从选定的切入点步步推进成稿。详细规范见 [GROUNDING.md](GROUNDING.md)。
- **改写**：可以调整信息顺序、拆分段落和重写句子，同时保留原意。
- **翻译**：先理解原文要表达的行为和关系，再用自然中文重新表达，不按原句结构逐句映射。
- **审校**：收敛阶段。用户要求修改稿时直接修正；用户只要求评审时，报告问题、影响和建议修改。重点审查是否存在未铺垫概念突降与逻辑跳步。

## 认知铺垫与推进单元

成文与重构时遵循以下原则，完整方法论与自查清单见 [GROUNDING.md](GROUNDING.md)：

- **认知铺垫（Grounding，先铺垫后引用）**：任何概念在被后续论述依赖或充当论据前，必须已在读者心智中建立清晰认知。认知铺垫途径唯二：读者进门自带的前置已知（Prerequisite），或在前置论述中正式引入并解释（Introduced）。严禁未铺垫概念突降。
- **推进单元（Beats）**：文章由一系列离散的推进单元构成。每个单元只做一个明确动作（铺设场景、确立论点、抛出设问、给出示例、反转视角、总结定论），依赖已铺垫认知，并为后续展开铺垫新概念。交互式构思时可提供候选推进方向；成稿撰写或自动触发时，在内部依据论述步调推演直接交付完整成稿。
- **按需取材与裁剪**：前期积累的素材是候选库，不是必须念完的宣讲脚本。可以按需取用、拆分、重组或大胆舍弃，无需把所有素材机械塞入；文章结束于叙事旅程的自然收束。
- **形式辩护**：散文段落 vs 列表、正文行内 vs 标注块（Callout）、表格 vs 重复结构的选择必须有充分表达依据。

## 审校顺序

### 1. 保持原意和事实

逐项对照原材料中的事实、主体、条件、范围、程度、时间、数字、权限、例外和不确定性。清晰化不能扩大承诺、缩小限制或把推测改成事实。

原文存在多种合理解释时，判断差异是否会改变事实、承诺、权限或下一步行动：

- 会改变时，明确指出歧义并请求确认；可以给出分别对应不同解释的候选写法。
- 不会改变时，采用最符合上下文的解释，并在有必要时简短标明。

发现事实或逻辑可能有误时，把它与语言修改分开处理。有可靠依据时另行提出修正建议；没有可靠依据时指出疑点并请求确认。

### 2. 审查认知铺垫与信息顺序

检查整篇内容的认知阶梯：任何在后文充当论据或核心前提的概念，是否均已在前文或作为读者预备知识完成铺垫。发现术语突降、未铺垫推论或认知断层时，在前置位置安排补足段落，或明确声明读者门槛。

让读者尽早看到本段或本文的主要结论，再提供理解结论所需的背景、依据、限制和下一步。文体要求采用其他顺序时，遵循文体要求。

检查段落与论述单元之间的推进关系是否明确：并列、递进、因果、转折、条件和时间顺序都应当能从内容或连接方式中看出来。每个推进单元围绕一个主要判断组织，相关的条件和例外放在判断附近。

### 3. 补齐前提和明确指代

补上目标读者理解结论所需、但原文省略的背景。新增内容可能改变事实时，改为指出信息缺口，不自行补写。

每个代词、简称和省略主语都应有唯一、就近的所指。多个主体可能被“他”“其”“该项”“前者”等词指代时，改用具体名称；具体名称仍不能消除重要歧义时，请求确认。

### 4. 调整句子和用词

- 一句话围绕一个主要判断组织。句中同时出现多个独立条件、动作或例外时，拆成几句或改用列表。
- 主体执行动作时优先使用主动、具体的表达，让读者看出谁做什么、产生什么结果。
- 保留目标读者熟悉且准确的专业术语。必要的陌生术语在首次出现时用直白语言解释。
- 普通动作使用自然中文。名词连续堆叠时，恢复其中的动作和关系。
- 隐喻只有在确实帮助理解时使用，并在首次出现时给出直白含义。
- 删除不增加含义的重复。细节是否必要不明确时予以保留或标明，不以字数少作为完成标准。

不设置固定句长、段长或术语数量。判断标准是目标读者能否一次读懂，而不是字符数量。

### 5. 统一书写形式

需要处理标点、数字、中英混排或正式文体时，阅读 [STANDARDS.md](STANDARDS.md)。项目已有写作规范时同时遵循项目规范。

## 输出

- 撰写、改写或翻译默认只交付成稿。
- 探索阶段的构思请求，交付结构化的构思素材、承重词与候选切入视角。
- 用户要求理由、修改记录或审校报告时，再说明关键问题和修改依据。
- 存在会改变含义的歧义、事实疑点或无法保真的内容时，先给出待确认项，不把一种猜测包装成定稿。

## 完成条件

交付前确认：

- 目标读者不需要猜测省略的前提、术语含义或代词所指，就能复述主要结论和下一步；
- 遵循先铺垫后引用的认知铺垫原则，论证链条没有突降术语或未铺垫的前提断层；
- 事实、约束、权限、数字、语气和不确定性与原意一致；
- 信息顺序符合文体和阅读目的；
- 中文变体、术语、标点和格式前后一致；
- 输出形式与用户请求阶段（探索构思 vs 收敛交付）一致，没有附加不需要的写作过程。
