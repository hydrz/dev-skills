# 认知铺垫与行文推进指南

本文件阐述中文技术写作、设计文档与深度长文从 0 到 1 的行文构思与认知阶梯组织规范。它提供动笔前的探索方法、行文中的概念推进法则与成文结构裁决标准，与 [STANDARDS.md](STANDARDS.md)（形式与标点规范）共同构成完整的中文写作体系。

## 两个阶段：探索与收敛

专业写作不是从第一句开始就线性打磨措辞，而是分为两个目标不同的阶段：

| 阶段 | 核心任务 | 关注点 | 交付标准 |
| :--- | :--- | :--- | :--- |
| **探索阶段（从零构思）** | 发掘想法碎片，寻找核心承重词，摸清读者认知基线 | 拓宽可能空间，不急于固定结构或挑剔词句，提炼高价值观点与案例 | 零散但真实的构思碎片池、前置已知认知集合、2 到 3 个候选切入起笔视角 |
| **收敛阶段（步调推进与审校）** | 选定叙事路线，步步开采原料，确保认知铺垫与逻辑咬合 | 严守认知阶梯，未铺垫的概念不得作为论据；单步推进，核验事实与形式辩护 | 逻辑自洽、无概念跳跃的成稿，或包含修改依据与前置补足建议的审校报告 |

### 探索阶段（从零构思）

在探索阶段，核心是发掘值得写的内容素材，避免过早陷入段落修辞或僵硬的大纲模板。

1. **采集构思碎片（Fragments）**：
   - 敏锐观察：在实践中发现的真实技术反直觉现象或团队痛点。
   - 核心论断：带有明确立场的一句话判断，附带一到两行理由。
   - 具象场景：一段真实发生的代码演进、异常堆栈、性能瓶颈或业务案例。
   - 关键承重词（Leading Word）：这是探索阶段最宝贵的产物。一个恰当命名的承重词（例如“示踪弹”“认知阶梯”“单向门”“采石场”）能为整篇文档提供核心意象与概念支点，后续的结构展开与论证过渡都将由此衍生。
2. **摸清读者底色（Prerequisites）**：
   - 在写下第一个字之前，必须与用户或根据目标读者画像明确：读者走进这篇文章时，脑海中默认已经掌握了哪些概念。
   - 这些概念构成最初的“已铺垫认知集合”。未在集合中的概念，后续必须先铺垫再使用。

### 收敛阶段（成文推进与审校）

在收敛阶段，探索告一段落，原料范围已经固定。此时需要确定一条清晰的叙事主线，将原料碎片作为采石场按需开采，严格依托先铺垫后引用的认知铺垫原则与清晰步调推进成文。

## 认知铺垫（Grounding，先铺垫后引用）原则

**核心法则**：任何概念在被后续论述依赖或充当推理前提之前，必须已在读者心智中稳固建立。未在前置章节明确铺垫的概念，严禁在后续论证中突兀作为论据引用。

### 1. 认知铺垫的两条途径

读者理解一个概念，只能通过以下两种途径之一：

- **前置已知（Prerequisite）**：读者在阅读本文前就已经熟知的概念，在开篇前明确厘定。
- **文中引入（Introduced）**：在文中的前置论述中正式阐述、定义、推导或具象化。一旦在文中建立认知铺垫，后续展开便可自由依赖并将其作为论据。

因此，每一个推进单元都在做两件事：

1. **依赖（Requires）**：依赖当前已经铺垫的概念集合；
2. **铺垫（Grounds）**：向读者引入并确立新的概念，解锁后续更深入的论据。

### 2. 严禁概念突降与跳步

- **概念突降**：如果在论证“为什么选择方案 B”时，突然冒出一句“因为方案 B 完美支持了向量时钟机制”，而前文从未解释什么是向量时钟或为什么需要它，读者就不得不中断当前阅读，陷入猜测或外部检索。这就是典型的概念突降。
- **概念模型优先于术语词汇**：认知铺垫的单位是“概念模型”，而不仅仅是“专业术语”。即使句子完全避开了行业黑话，如果突兀引入了一个读者未曾理解的底层假设或抽象机理，读者同样会脱离地面。当一个概念拥有正式技术名称时，认知铺垫要求将“机制内涵”与“术语名称”一同交代清楚。

### 3. 认知门槛的权衡

- **门槛定得太高（设过多前置已知）**：正文固然精简，但将大量读者拒之门外，文章变成少数人才能读懂的黑话堆叠。
- **门槛定得太低（文中铺垫过多常识）**：开篇被无休止的入门定义淹没，拖累叙事主线，令资深读者失去耐心。
- **应对方案**：根据文档定位明确读者画像。如果后文必须使用某项关键概念，但它不属于目标受众的通识，就在前置位置设立专门的铺垫段落，或在篇首醒目位置声明预备知识要求。

## 推进单元（Beats）与行文步调

文章不是一段毫无停顿的长途跋涉，而是由一系列步调清晰的“推进单元”层层展开的认知旅程。

### 1. 什么是推进单元

推进单元是叙事或论证中的最小步进单元。一个推进单元只做**一个明确的动作**：

- **铺设场景**：呈现现状、业务背景或系统所处的初始状态。
- **确立论点**：抛出本节或本文的核心主张。
- **抛出设问**：引发读者的探究欲望，指出反直觉现象或待解难题。
- **给出示例**：提供一段直观代码、输入输出对比或场景推演。
- **反转视角**：指出普遍认知的盲点，纠正先入为主的偏见。
- **总结定论**：在当前证据充分的基础上得出阶段性推论。

完成这个动作后，当前论述就应当收敛，给读者消化思考的空间，并为下一步展开留出过渡接口。

### 2. 推进单元的颗粒度

推进单元的大小取决于该动作所需的最小篇幅，而不是死板的字数限制：

- **单句推进**：干脆有力的关键转折（例如：“但是随后的整整三周里，什么都没有发生。”）。
- **短段落推进**：需要背景交代或逻辑铺陈的论述块。
- **多段落推进**：包含自洽案例、代码推演和结果对照的综合展示块。

> [!WARNING]
> 如果一个推进单元包含了五个段落和三个层级的小标题，它就不是单个推进单元，而是多个论述动作粘连在一起的产物。应将其果断拆解。

### 3. 步步为营的推进流程

行文的具体推进方式取决于交互场景：

- **交互式人机共创构思**：当用户希望一同推敲文章走向、探索不同切入点时，采取单步推进与候选走向机制：
  1. **锚定前置已知**：与读者画像对齐初始已铺垫认知集合。
  2. **拟定候选切入点**：从原料中提炼 2 到 3 个切入视角不同的起笔候选（Starting Beats）。每个候选起笔只能基于已铺垫概念，并标明它将解锁哪些新认知。由用户选定其一。
  3. **落实单步成文**：选定切入点后，只撰写这一步的内容并暂停。
  4. **规划后续走向**：重新审视当前已铺垫的概念集合，提供 2 到 3 个候选下一步推进方向（Next Beats），指明每个方向的逻辑转向与解锁概念，由用户抉择。
  5. **循环迭代至终局**：重复推进，直至文章核心目标圆满达成。
- **直接交付成稿或自动触发**：当用户明确要求直接产出完整成稿，或由其他 agent、工作流自动调用本 skill 时，**严禁中途暂停或抛出未完成的走向选项**。agent 应在内部自主基于认知铺垫完成论述步调推演与链条校验，直接交付结构完备、逻辑自洽的成篇内容，严格与 [SKILL.md](SKILL.md) 中“默认只交付成稿”的交付原则保持一致。

## 原材料开采与排版形式辩护

### 1. 将原料堆作为采石场

在收敛阶段，探索期积累的碎片是采石场（Quarry），而不是死板的宣讲脚本：

- 可以对碎片进行转述、拆分、重组或提炼，使其完全融入当前推进单元的叙事语调。
- 原料堆中有剩余碎片是完全正常的。文章结束于论证旅程的自然收束，而不是将全部原料生硬塞入。
- 当推导链条需要某个具象支撑（如对比测试数据）而原料堆中缺失时，必须明确指出信息缺口，及时补齐或调整论证结构，绝不含糊带过。

### 2. 排版形式辩护

选择何种视觉排版形式，应当具有明确的逻辑依据：

- **散文段落 vs 列表**：散文段落承载因果推演与细腻逻辑；列表用于承载对等的并列项与快速信息扫读。若各项之间存在先后依赖或轻重主次，改用散文段落。
- **正文行内 vs 标注块（Callout）**：只有次要提示、额外警告或环境旁白确实会严重打断正文逻辑时，才使用标注块（`> [!NOTE]`、`> [!TIP]`、`> [!WARNING]`）；核心论证与结论必须留在正文主干中。
- **表格 vs 重复结构**：只有当存在 3 组以上、具有完全相同对比维度的对象时，才使用表格；字段不一致或零散对比使用带加粗导语的散文段落。
- **原话引用 vs 意译转述**：只有原文的具体措辞本身具有不可替代的证据价值时才使用引用；若只需传递事实或逻辑，使用自然中文重新表达。
- **代码块 vs 行内代码**：可运行脚本、多行逻辑或具有缩进结构的代码使用代码块；单个类型名、命令参数或标识符使用行内代码。

## 认知铺垫与行文推进自查清单

成文或审校时，逐项核对以下问题：

- [ ] **前置边界**：读者走进文档时已知的概念基线是否清晰明确？
- [ ] **认知铺垫**：后文出现的每个关键论据、机制与术语，是否均在前置论述中完成认知铺垫？
- [ ] **杜绝突降**：是否存在读者尚未理解就被默认当作真理引用的抽象概念？
- [ ] **单一动作**：每个推进单元是否只聚焦完成一个叙事或论证动作？是否存在臃肿粘连？
- [ ] **承重词**：全文是否围绕清晰有力的核心承重词展开，且该词在首次出现时已给出直白解释？
- [ ] **形式辩护**：文档中的列表、表格、代码块与标注块，是否都有不可替代的排版理由？
- [ ] **自然收束**：文章是否在达成核心目标与结论后干脆收尾，没有为了消耗剩余素材而节外生枝？
